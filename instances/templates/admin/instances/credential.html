The obvious way to do this is `messages.warning`, and that is what the first version did. Django's default MESSAGE_STORAGE is FallbackStorage, which tries CookieStorage first -- so a message this size goes into a COOKIE: written to the operator's disk by their browser, sent back on the next request, and visible to anything that logs request headers. A credential that never travels is the whole argument for the HMAC scheme in `instances/auth.py`, and putting one in a cookie to tell somebody about it gives that back. So it is rendered here, in the body of one response, and stored nowhere. {% endcomment %} {% block content %}
